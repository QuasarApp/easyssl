# Migration from Qt-Secret to EasySSL

The [Qt-Secret](https://github.com/QuasarApp/Qt-Secret) library is no longer
maintained. Its README now recommends to use the [EasySSL](https://github.com/QuasarApp/easyssl)
library instead. EasySSL is a Qt wrapper of the OpenSSL 3.0+ library and it
provides the same core features as Qt-Secret (RSA encryption, signing, key
generation) with better security and performance.

This document describes how to migrate your project from Qt-Secret to EasySSL.

## Feature comparison

| Feature | Qt-Secret | EasySSL |
|---------|-----------|---------|
| RSA encryption | yes | yes |
| RSA decryption | yes | yes |
| RSA signing | yes | yes |
| ECDSA signing | no | yes |
| X509 self-signed certificates | no | yes |
| Asynchronous keys authentication | no | yes |
| AES | yes | **no** (see below) |
| Key format | custom raw byte arrays (BigInt) | standard PEM (PKCS#8 / SPKI) |
| Signature format | custom: `message + marker + hexSignature + marker` | standard OpenSSL `EVP_DigestSign` with the SHA-256 digest (RSA PKCS#1 v1.5 / ECDSA), the signature bytes only |
| OpenSSL dependency | no | yes (OpenSSL >= 3.0) |

> **Warning:** EasySSL does **not** support AES. If your project depends on the
> `QAESEncryption` class you need to keep the Qt-Secret AES code (or the
> [Qt-AES](https://github.com/bricke/Qt-AES) submodule) for the symmetric
> encryption part, or implement the symmetric encryption on the OpenSSL
> primitives yourself. EasySSL is only an asymmetric cryptography library
> (RSA/ECDSA).

## Key format changes

This is the most important difference between the two libraries:

* **Qt-Secret** keys are custom raw byte arrays generated by the built-in
  BigInt implementation. They can not be used by any other library.
* **EasySSL** keys are standard **PEM** encoded keys:

      ```
      -----BEGIN PRIVATE KEY-----
      MIIEvQIBADANBg...
      -----END PRIVATE KEY-----
      ```

**The Qt-Secret keys are not directly compatible with EasySSL.** You can not
load a Qt-Secret key into the EasySSL library (and you can not load an EasySSL
PEM key into Qt-Secret). After the migration you must generate the new keys
with EasySSL and distribute them again.

## Signature incompatibility

The Qt-Secret `signMessage` method returns the **concatenation** of the
original message and the signature in a custom format:

```
message + SIGN_MARKER + hexSignature + SIGN_MARKER
```

The EasySSL `signMessage` method returns **only the signature** bytes and the
`checkSign` method takes the message and the signature as separate arguments.

Because of that:

* the old Qt-Secret signed messages can **not** be verified by EasySSL,
* the EasySSL signatures can **not** be verified by Qt-Secret,
* a mixed deployment (some clients on Qt-Secret, some on EasySSL) is not
  possible. All sides must be switched to EasySSL at the same time.


## API mapping

| Qt-Secret | EasySSL |
|-----------|---------|
| `QRSAEncryption e(QRSAEncryption::Rsa::RSA_2048)` | `EasySSL::RSASSL crypto;` |
| `QRSAEncryption::Rsa::RSA_2048` (key size) | the `RSASSL` default key size is 3072 bits (see the note below) |
| `e.generatePairKey(pub, priv)` | `crypto.makeKeys(pub, priv)` |
| `QRSAEncryption::generatePairKey(pub, priv, QRSAEncryption::Rsa::RSA_2048)` | `EasySSL::RSASSL crypto; crypto.makeKeys(pub, priv);` |
| `e.encode(msg, pub)` | `crypto.encrypt(msg, pub)` |
| `e.decode(encrypted, priv)` | `crypto.decrypt(encrypted, priv)` |
| `e.signMessage(msg, priv)` | `crypto.signMessage(msg, priv)` |
| `e.checkSignMessage(signedMessage, pub)` | `crypto.checkSign(msg, signature, pub)` |
| `QAESEncryption` | **not supported** |
| `QRSAEncryption::BlockSize` | `EasySSL::RSASSL::RSAPadding` (`PKCS1_OAEP_PADDING` is the default) |

### RSA: before / after

Qt-Secret:

```cpp
#include <qrsaencryption.h>

int main() {
    QRSAEncryption e(QRSAEncryption::Rsa::RSA_2048);
    QByteArray pub, priv;
    e.generatePairKey(pub, priv);

    QByteArray msg = "Hello Qt-Secret!";
    auto encryptMessage = e.encode(msg, pub);
    auto decodeMessage = e.decode(encryptMessage, priv);
    // decodeMessage == msg

    auto signedMessage = e.signMessage(msg, priv);
    if (e.checkSignMessage(signedMessage, pub)) {
        // the message is signed
    }
}
```

EasySSL:

```cpp
#include <easyssl.h>
#include <easyssl/rsassl.h>

int main() {
    if (!EasySSL::init())
        return -1;

    EasySSL::RSASSL crypto; // the default key size is 3072 bits

    QByteArray pub, priv;
    crypto.makeKeys(pub, priv);

    QByteArray msg = "Hello EasySSL!";
    auto encryptMessage = crypto.encrypt(msg, pub);
    auto decodeMessage = crypto.decrypt(encryptMessage, priv);
    // decodeMessage == msg

    auto signature = crypto.signMessage(msg, priv);
    if (crypto.checkSign(msg, signature, pub)) {
        // the message is signed
    }
}
```

> **Note about the key size:** the Qt-Secret `RSA_2048` constant has no
> public counterpart in EasySSL: the `RSASSL` class uses the 3072 bits key
> size by default and the key size / padding enums (`RSABits`, `RSAPadding`)
> are declared private in the public headers, so only the default
> configuration is accessible from the user code. The 3072 bits keys are
> more secure than the 2048 bits keys, so they are a safe replacement.

### AES: not supported

The Qt-Secret `QAESEncryption` class has **no** EasySSL counterpart:

```cpp
// Qt-Secret
#include "qaesencryption.h"

QAESEncryption encryption(QAESEncryption::AES_128, QAESEncryption::ECB);
QByteArray encodedText = encryption.encode(plainText, key);
QByteArray decodedText = encryption.decode(encodedText, key);
```

If your project uses AES, you should keep the Qt-AES code for the symmetric
part and use EasySSL only for the RSA/ECDSA part, or implement the AES
encryption directly on the OpenSSL symmetric primitives.

## Migration steps

1. Add the EasySSL library to your project (see the
   [USAGE.md](USAGE.md) document for the CMake and qmake instructions).
2. Replace the `QRSAEncryption` usage with the `EasySSL::RSASSL` usage
   (see the API mapping table above).
3. Call the `EasySSL::init()` method at the start of your application.
4. Regenerate all the keys with the new library. The old Qt-Secret keys can
   not be used.
5. Re-sign all the stored data (signatures) or invalidate the old signatures.
6. If your project uses AES, keep the Qt-AES part or replace it with the
   OpenSSL symmetric primitives.
7. Remove the Qt-Secret sources and the mini-gmp / Qt-AES submodules from
   your project.
